## Жёсткие правила
- Не добавлять Profile B-специфику (Reality, Fallbacks, nginx) в `transport-api` или `protocol`.
- Profile A должен собираться и работать без домена, сертификата и nginx.
- Политика выбора транспорта не переключает профиль автоматически.
- Не реализовывать собственную криптографию.
- Не логировать payload, credentials, ключи.
- Клиентская аутентификация (mTLS per-client, ADR-021) — обязательный слой
  перед P4/P5; транспорты без аутентификации не добавлять. Секреты клиентов
  хранятся только в `crypto::Secret` (без `Debug`/`Display`).
- При добавлении зависимости проверять MSRV. Транзитивные пины
  (например, `time = "=0.3.36"`) документировать в ADR-018.
- Inline-секреты (PEM, ключи) не должны попадать в `Display`/`Debug` ошибок
  конфигурации. Проверять при изменениях `crates/config`.
- `Transport` в MVP — синхронный. Не вводить `tokio` или async-контракт в `transport-api` без ADR-017. Async — Phase 2.
- MSRV = 1.85 (ADR-018). Не понижать без нового ADR. Не использовать
  edition2024 в собственном коде без отдельного решения.
- Сертификаты: CA + leaf, не self-signed. Dev-ключи — только для
  тестов/демо. Production-секреты — только через CI-secrets/env.
- Оптимистичный SOCKS5 REP_SUCCESS — временное решение (ADR-019).
  Не переносить его в Phase 2 или production без пересмотра ADR.
- IPv6-цели: relay должен корректно обрабатывать ATYP=IPv6.
  End-to-end тест с IPv6-целью обязателен в следующем спринте.
- Commit без remote — операционный долг. При следующем коммите
  напомнить владельцу про настройку remote и CI.
- Клиентская аутентификация — обязательный слой перед P4/P5.
  Не добавлять транспорты, DPI-механизмы или второй профиль, пока
  клиент не идентифицирован (ADR-021).
- Адресные правила: `allow_ports_low` по умолчанию включает 80 и 443.
  Не убирать их без обоснования — это ломает UX.
- `socks5-limitations.md` — единственный источник известных ограничений
  SOCKS5-режима. При исправлении ограничения — обновлять файл,
  не оставлять «исправлено, но не задокументировано».
- Docker-образы (ADR-011) — обязательный артефакт. Если `deploy/docker/`
  пуст, это операционный долг, а не «следующий шаг».
- Решения, влияющие на отзыв, аудит или аутентификацию, оценивать
  по модели угроз ADR-021, а не по производительности. Обход
  `verify_client_cert` (session resumption, PSK, 0-RTT, любые
  механизмы, восстанавливающие сессию без полного handshake) —
  не «нюанс», а изменение security-свойств; требует явного ADR
  с разделом «Что ломается: отзыв / аудит / max_sessions».
- При добавлении транспорта (P4, QUIC) проверить, есть ли у него
  0-RTT или session resumption. Если есть — по умолчанию отключить,
  пока не доказано, что resumed-сессии проходят клиентскую
  аутентификацию и аудит.

## Режимы клиента (три независимые оси)
- `mode`: `socks5` — MVP и обязательный; `tun` — Phase 2, в MVP его нет.
- `entry`: `none` — MVP по умолчанию; `wireguard` — MVP, опционально (AmneziaWG, не голый WireGuard).
- `profile`: `direct` — MVP; `camouflaged` — MVP, опциональный.

## SOCKS5
- SOCKS5 — полноценный режим MVP, не «только для контейнера».
- Не требует root, `NET_ADMIN`, не меняет маршруты и DNS хоста.
- Не смешивать код SOCKS5 и TUN в одном модуле без явной границы.
- UDP ASSOCIATE в MVP отклоняется с понятной ошибкой (без тихого fallback).

## TUN
- TUN — Phase 2. Не реализовывать в MVP.
- При упоминании TUN в коде или документации помечать как Phase 2.

## wireguard-entry
- `entry = wireguard` — это AmneziaWG, не голый WireGuard.
- Голый WireGuard в целевой среде не работает; не предлагать его как вариант.
- Рекомендуемая комбинация в MVP: `entry = wireguard` + `mode = socks5`.
- `entry = wireguard` + `mode = tun` откладывается вместе с TUN (Phase 2).
- Параметры обфускации AmneziaWG должны быть одинаковыми на обеих сторонах;
  при их отсутствии соединение падает молча.
- TCP/443-режим AmneziaWG обязателен для мобильных операторов РФ.
- Минимальная версия — AmneziaWG 3.1 (2.x несовместим с 3.1).

## Профили развёртывания
- A (Direct) — MVP, обязательный.
- B (Camouflaged entry) — MVP, опциональный.
- C (CDN-fronted) — только после ADR.
- D (Serverless) — исследовательский, не в MVP.
