# ADR-011: Контейнеризация клиента и сервера

## Статус: Принято

## Решение
1. Контейнерные образы для клиента и сервера — обязательный артефакт релиза.
2. Основной контейнерный сценарий клиента — SOCKS5. TUN в контейнере —
   не в MVP (см. ADR-012).
3. Контейнер не требует `--privileged`.
4. Образы — multi-stage, non-root, distroless/slim.
5. Версионирование — semver + digest, не `latest` в production.
6. CI собирает образы и выполняет smoke-тест `docker run` на P1.
7. Серверный контейнер: `read_only: true`, `no-new-privileges: true`,
   `cap_drop: [ALL]`, non-root user, `tmpfs`, лимиты `memory`/`pids`/`cpu`.
8. Секреты — через secrets/volume, не в образе и не в `ENV`.
9. Логи — в stdout/stderr.
10. Образы подписываются (cosign); SBOM для образов.
11. Клиент с `entry = wireguard` требует проброса порта (UDP/TCP 51820
    или 443) и не входит в минимальный smoke-тест.

## Последствия
- Нативная установка клиента с TUN остаётся основным путём для пользователя
  после Phase 2.
- Profile B требует отдельного образа с nginx; он не является зависимостью
  образа Profile A.
