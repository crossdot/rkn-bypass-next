# ADR-016: wireguard-entry (AmneziaWG) как режим клиента

## Статус: Принято (MVP, опционально)

## Контекст
Схема: конечные пользователи → клиент с запущенным AmneziaWG-сервером
→ заграничный сервер. Клиент выступает точкой входа для других устройств.

## Решение
1. Вводится ось `entry` (`none` | `wireguard`) отдельно от `mode` и `profile`.
2. `entry = wireguard` использует AmneziaWG, не голый WireGuard.
   Голый WireGuard блокируется ТСПУ по handshake с начала 2026.
3. Рекомендуемая комбинация в MVP: `entry = wireguard` + `mode = socks5`.
   TUN-режим — Phase 2; комбинация `entry = wireguard` + `mode = tun`
   откладывается вместе с TUN.
4. TCP/443-режим AmneziaWG обязателен для мобильных операторов РФ
   (UDP может блокироваться).
5. Параметры обфускации (Jc, Jmin, Jmax, S1-S4, H1-H4) должны совпадать
   на клиенте-точке-входа и подключаемых устройствах; при несовпадении
   соединение падает молча.
6. Минимальная версия AmneziaWG — 3.1 (2.x несовместим с 3.1,
   требуется перевыпуск профилей).
7. Управление доступом конечных пользователей выполняется на
   клиенте-точке-входа; отзыв доступа немедленно блокирует трафик.
8. Клиент-точка-входа требует публичного IP или проброса порта.

## Последствия
- Появляется новый модуль `wireguard-entry` в крейтах клиента.
- Тесты AmneziaWG (UDP и TCP/443) добавляются в P5.2.
- Docker-сценарий клиента с `entry = wireguard` требует проброса порта
  и не входит в минимальный smoke-тест.
- TUN-совместимость wireguard-entry откладывается до Phase 2.
