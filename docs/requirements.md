# Requirements

## Целевая среда эксплуатации

Система проектируется для работы в условиях Российской Федерации:

- активное применение ТСПУ (inline DPI) на сетях крупных операторов;
- блокировка протоколов (SOCKS5, VLESS, L2TP, OpenVPN, WireGuard и их форков)
  на уровне DPI-сигнатур и поведенческих эвристик;
- блокировки на уровне NSDI (DNS);
- блокировки по SNI и по IP-подсетям хостингов;
- «белые списки» на мобильных сетях (доступ только к разрешённым ресурсам);
- удаление клиентов из российского App Store;
- давление на платформы с целью выявления пользователей VPN;
- атаки на инфраструктуру провайдера (DDoS, фишинг, массовые блокировки подсетей);
- фильтрация облачной инфраструктуры целиком по поведенческим признакам.

**Не цель:** обход блокировок за пределами РФ. Соответствующие сценарии
не тестируются и не поддерживаются.

**Юридическая рамка:** факт использования VPN не является правонарушением;
ответственность может возникать за рекламу VPN и за умышленный поиск
запрещённых материалов. Система не должна содержать функций, явно
позиционирующих её как средство доступа к запрещённому контенту.

## Режимы работы клиента

Клиент имеет три независимые оси конфигурации:

| Ось | Значения | Что означает |
|---|---|---|
| `mode` | `socks5` (MVP), `tun` (Phase 2) | Как клиент принимает трафик от приложений на том же устройстве |
| `entry` | `none` (MVP), `wireguard` (MVP, опционально) | Принимает ли клиент трафик от других устройств через AmneziaWG |
| `profile` | `direct` (MVP), `camouflaged` (MVP) | Как клиент соединяется с заграничным сервером |

Оси независимы; валидные комбинации определяются ниже.

### SOCKS5-режим (обязательный, MVP)

- Локальный SOCKS5-прокси (TCP CONNECT).
- Не требует root, `NET_ADMIN` или изменения системных маршрутов.
- Работает в контейнере и нативно.
- Не управляет DNS и маршрутами хоста; приложения используют прокси явно.
- Основной сценарий для контейнерного клиента (ADR-011, ADR-012).
- Поддерживает оба профиля: A (Direct) и B (Camouflaged entry).

### TUN-режим (Phase 2 — после SOCKS5)

- Системный туннель, управление маршрутами и DNS.
- Требует привилегий (см. P6.5).
- Нативно — основной путь для конечного пользователя после реализации.
- В контейнере — только через sidecar с `NET_ADMIN` (ADR-012, не в MVP).
- Поддерживает оба профиля: A и B.
- **Не входит в MVP.** Реализуется после стабилизации SOCKS5-режима,
  транспортов и wireguard-entry.

Режим выбирается в конфигурации клиента (`mode = "socks5" | "tun"`).
Профиль развёртывания (`profile = "direct" | "camouflaged"`) выбирается
независимо. Комбинации mode × profile валидны во всех вариантах;
TUN-комбинации помечены как Phase 2.

## Режим wireguard-entry (AmneziaWG)

Клиент может выступать точкой входа для других устройств, принимая
подключения по AmneziaWG. Схема: конечные пользователи → клиент
с запущенным AmneziaWG-сервером → заграничный сервер.

### Обязательные условия
- Используется **AmneziaWG**, не голый WireGuard. Голый WireGuard
  блокируется ТСПУ по handshake с начала 2026.
- Параметры обфускации (Jc, Jmin, Jmax, S1-S4, H1-H4) должны совпадать
  на клиенте-сервере и на подключаемых устройствах.
- На мобильных операторах (МТС, Мегафон, Билайн, Tele2) UDP может быть
  заблокирован; клиент должен поддерживать TCP/443-режим AmneziaWG.
- `entry = wireguard` несовместим с `mode = tun` на одном интерфейсе
  без явного разделения TUN-устройств. Рекомендуемая комбинация:
  `entry = wireguard` + `mode = socks5`.

### Ограничения
- Клиент-точка-входа требует публичного IP или проброса порта.
- AmneziaWG-сервер на клиенте потребляет CPU и память; лимиты должны
  быть явно заданы.
- Отзыв доступа конечного пользователя выполняется на клиенте-точке-входа,
  а не на заграничном сервере.

## Профили развёртывания точки входа

### Profile A — Direct (MVP)
VPS с открытым портом, TLS с валидным сертификатом на домене.
Минимальная конфигурация; подходит для сетей без активного DPI
и как fallback. Не требует nginx, фейкового сайта или Reality.

### Profile B — Camouflaged entry (self-steal, MVP)
VPS + домен + фейковый веб-сайт, отдаваемый через Fallbacks
при неаутентифицированных TLS-соединениях. Reality как механизм маскировки.
Требует валидного сертификата и автоматической ротации.
Рекомендуется для сетей с активным ТСПУ.

### Profile C — CDN-fronted (экспериментальный, после ADR)
Точка входа за CDN или российским облаком с «белыми» IP.
Схема хрупкая: аккаунты массово блокируются, работоспособность
зависит от региона и оператора.

### Profile D — Serverless-мосты (исследовательский, не в MVP)
Использование serverless-функций в качестве динамически создаваемых мостов.

Профили не являются взаимоисключающими на уровне инфраструктуры.
Клиент выбирает профиль по явной команде/конфигурации,
но не переключается между профилями автоматически без явной политики.
