# Слои развёртывания и границы ответственности

1. **Прикладной протокол** (`protocol`) — сообщения, версии, лимиты.
   Не знает о транспорте и профиле.

2. **Транспорт** (`transport-api`, реализации) — контракт соединения
   и передачи данных. Не знает о Fallbacks, nginx, сертификатах, домене.
   Не знает о `mode` и `entry`.

3. **Профиль развёртывания** (`deploy/profiles/`) — Fallbacks, nginx,
   фейковый сайт, сертификаты, домен. Не протекает в `transport-api`.

4. **Режим клиента** (`mode`, `entry`) — слой приложения.
   SOCKS5 и wireguard-entry не смешиваются с транспортом.

5. **Конфигурация** (`configs/`) — выбор режима, entry, профиля, транспорта.

## Правила
- Транспорт не предоставляет API для управления Fallbacks, сертификатами,
  nginx, доменом, SOCKS5 или AmneziaWG.
- `cargo build` и базовый Docker-образ сервера не требуют nginx,
  домена или сертификата.
- Политика выбора транспорта не переключает профиль автоматически.
- TUN — Phase 2; в MVP его нет.

## Модель исполнения транспорта
- **MVP (P2/P3):** `Transport` — синхронный трейт (`std::io`-стиль).
  Реализация TLS — `rustls` (sync, `rustls::StreamOwned` с
  `std::net::TcpStream`). Сервер и клиент — thread-per-connection.
- **Phase 2 (после SOCKS5 с конкурентными соединениями):** async-контракт.
  Реализация — `tokio-rustls` + `tokio::net::TcpStream`. Требует ADR-017.
- Переход sync → async не требует смены TLS-конфигурации: `rustls`
  спроектирован как sans-I/O, `ClientConfig`/`ServerConfig` переносятся
  без изменений.
- Смена контракта `Transport` (sync → async) — отдельное проектное
  решение, фиксируется ADR-017 до реализации.
