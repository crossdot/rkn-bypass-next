# Beta-процесс (P10)

Beta — это **процесс**, не флаг в коде. `--beta` не вводится (потребовал бы ADR).

## 1. Отдельный сервер

- Отдельный VPS/инстанс, отдельные сертификаты (свой CA) — не пересекается с
  production.
- Тот же релизный артефакт (тег), что и планируемый production.

## 2. Отдельные записи клиентов

В `clients.toml` beta-сервера — только beta-клиенты, с лимитами:

```bash
export CLIENTS_PATH=/etc/netcore/clients.toml
export CLIENTS_DIR=/etc/netcore/clients
admin-cli client add beta-alice --max-sessions 2
admin-cli client add beta-bob
```

Приватные ключи — только beta-пользователям. Отзыв: `admin-cli client revoke
<id>` (немедленно блокирует новые сессии).

## 3. Сбор логов и метрик

- `journalctl -u rkn-server` — аудит handshake/выбора транспорта, ошибки,
  `SIGSYS` (runtime-фильтр), `session limit`.
- `systemd-analyze security` — score.
- Периодически — нагрузочный smoke (`scripts/load.sh --clients 10 --duration 30`).
- Никаких payload/ключей в логах (ADR-021).

## 4. Канал обратной связи

- Отдельный канал (тикеты/чат), шаблон: версия/тег, транспорт (`tls|quic|auto`),
  регион/оператор, симптом, `journalctl`-фрагмент (без секретов).

## 5. Критерии выхода из beta

- Нет ошибок/SIGSYS в логах за период.
- e2e/нагрузочный smoke стабильны.
- Нет регрессий по сравнению с предыдущим релизом.
- Собраны отзывы, известные ограничения задокументированы.

## 6. Ограничение

Beta не меняет код и не вводит новый режим; это организационная изоляция
пользователей/сервера + сбор данных.
